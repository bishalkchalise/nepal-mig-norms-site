Website result schema

All website assets are produced by analysis/common/export_website.R from clean/data/derived/results_<paper>.csv (written by analysis/<paper>/estimate.R) and live in clean/data/website/ (copied to site/data/ at build time). The website never parses displayed text; every number on every page comes from these files.

Files

File Content
config.json every configuration list the front end needs: site/papers, shares, shifters, controls, treatments, samples, weights, estimators, defaults, outcome families per paper, build metadata
results_violence.json, results_gender_norms.json compact column-oriented result rows (see below)
results_<paper>.csv the same rows, one per line, all columns
diagnostics.json exposure distribution, concentration, destination contributions, leave-one-out, lead placebo, clustering, balance, shifter-vs-macro (see analysis/common/diagnostics.R)
descriptives.json Data-page descriptives: annual permits, destination shares, district intensity, shifter baseline/later/change + series, exposure points/histograms, DHS outcome means by wave, INSEC/court annual rates, sample table (see analysis/common/descriptives.R)
build_meta.json build_id (12 hex chars: md5 over the per-paper result-file hashes), generated_at, git_commit, per-paper row/spec counts and the set of option ids actually present

Identifiers

  • config.json also carries ladder (controls ladder order), main_results (dhs_ladder, admin_ladder, preferred_column), per-share primary, per-outcome key, per-paper hierarchy/flow.
  • spec_id = {paper}.{family}.{share_id}.{shifter_id}.{treatment_id}.{control_id}.{sample_id}.{estimator}.{weight_id} — readable and deterministic; e.g. violence.dhs_ipv.flow_2009_2012.unvaw.total.full.main.rf.dhs.
  • result_id = {spec_id}.{outcome_id}.{term}.
  • URL state on Results pages uses the same ids: results.html?outcome=<family>&share=…&shift=…&treatment=…&controls=<block|compare>&sample=…&estimator=…&weight=….

Row fields

Field Meaning
paper violence / gender_norms
spec_id, result_id as above
estimator rf, ols, fs, iv (DHS); stacked, level (admin)
outcome_family, outcome_id, outcome_label family and outcome ids/labels from config/outcomes_*.yml
term, term_label Z_total, Z_male, Z_female, or husband_is_away (ols/iv rows)
share_id, shifter_id, treatment_id, control_id, sample_id, weight_id option ids
fixed_effects, cluster, controls_label, weight_label, waves, reference_category human-readable specification metadata (stored once per spec_id in the JSON, repeated in the CSV)
beta, se, p_value, stars, ci_low, ci_high point estimate, cluster-robust SE, p, stars (* p<.10, ** p<.05, *** p<.01 — recomputed from p at export and verified at build), 95% CI with t(G−1) critical value
n, n_clusters observations used by the fit; number of district clusters
depvar_mean (weighted) mean of the dependent variable in the estimation sample
iqr_m inter-quartile range of baseline intensity for the term's channel and window
scaled_beta beta × iqr_m (DHS: outcome units); admin: 100·(exp(beta × iqr_m) − 1) (%)
effect_pct admin only: 100·(exp(beta) − 1)
p_channel_equality gendered treatment: p-value of β_male = β_female (t with G−1 df, clustered vcov)
first_stage_coef, first_stage_se, first_stage_f, first_stage_f_robust, partial_r2 iv/fs rows only: first-stage coefficient on the (first) instrument, conventional F (ivf1), cluster-robust Wald F (ivwald1), partial R² of the instruments
unit outcome unit from config (share, SD, years, count, …)
generated_at, git_commit time stamp and repository commit of the estimation run

Compact JSON layout

{ "paper": "violence", "generated_at": "...", "git_commit": "...",
  "columns": ["spec_id","estimator", ...],
  "spec_meta": { "<spec_id>": {"fixed_effects": "...", "cluster": "...", ...}, ... },
  "rows": [[...], [...], ...] }

shared/js/results-core.js expands it into row objects at load time.

Guarantees enforced at build (scripts/build_site.py)

  • every id in a result row exists in config;
  • stars match p-values;
  • every headline result configured in config/site.yml has a row at the paper's default specification;
  • no violence outcome id appears in a gender-norms family;
  • all internal links resolve; no local absolute paths in any page.
